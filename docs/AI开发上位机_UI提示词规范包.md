# AI 全量开发上位机 —— UI 提示词规范包

> 适用场景：LoRa 局放监测上位机（多路表格 + 曲线 + 报警）
> 用法：把 `design.md` 和 `rules.md` 两部分内容，在每次让 AI 写 UI 代码时**一起贴给它**。

---

## 一、design.md —— 有什么（纯规范，无歧义）

```markdown
# Design Tokens

## 主题
mode: dark（工业深色主题）
base_font: 14px（表格正文）/ 12px（标签）/ 20px（大数值读数）

## 颜色（只能用这些，禁止自创 hex）
--bg-app:        #12161F   主背景
--bg-panel:      #1A2030   面板/卡片背景
--bg-elevated:   #222A3D   悬浮层、弹窗
--border:        #2C3549   分割线、边框
--text-primary:  #E8ECF4   主文字
--text-secondary:#8A94A8   次要文字/标签
--text-disabled: #4A5265   禁用态

--accent:        #2E7CF6   主色/交互高亮

## 状态色（报警分级专用，语义不可混用）
--status-normal: #22C55E   正常（绿）
--status-watch:  #EAB308   关注（黄）
--status-warn:   #F97316   预警（橙）
--status-alarm:  #EF4444   报警（红）
--offline:       #6B7280   离线（灰）

## 间距（4px 栅格，只允许这些值）
xs:4px | sm:8px | md:12px | lg:16px | xl:24px | 2xl:32px

## 圆角
sm:4px | md:6px | lg:10px

## 字号阶梯
h1:20px/700  h2:16px/600  body:14px/400  caption:12px/400  num:20px/700(等宽)

## 可用组件（只能从这些里选）
Panel / StatCard / DataTable / StatusDot / AlarmBanner / TimeSeriesChart / Gauge
Button(variant: primary|secondary|danger|ghost, size: sm|md)
Badge(variant: normal|watch|warn|alarm)
Switch / Select / NumberInput / Tooltip / Tabs / Modal
```

## 二、rules.md —— 怎么用（约束与禁令）

```markdown
# UI 生成规则

## 布局规则
- 全部使用 Grid / Flex 布局，禁止绝对定位、禁止 magic number 坐标
- 每个容器必须指定尺寸策略：固定区用固定值，伸缩区用比例（如 3fr / 2fr）
- 主内容区必须可滚动，不允许内容溢出被裁切
- 窗口最小尺寸 1280×720，低于此值内部滚动而非压缩控件

## 状态色使用规则（严格）
- StatusDot 颜色只由 alarm_level 驱动：0=normal 1=watch 2=warn 3=alarm
- 离线节点：整行降透明度至 0.45，StatusDot 置灰
- 一屏内最多一个 primary 按钮

## 数值显示规则
- 实时读数用等宽字体，固定小数位（强度保留 1 位小数）
- 数值为空/无效显示 "--"，禁止显示 NaN / null / 0 占位
- 单位紧跟数值，用较小字号和次要色

## 表格规则
- 表头固定，内容区滚动
- 数值列右对齐，文本列左对齐，状态列居中
- 行高固定 36px，禁止内容撑高
- 超过 1000 行必须虚拟滚动或分页

## 曲线规则
- 多曲线可勾选显示/隐藏，颜色从预设色板取，不随机
- 必须显示：网格线、坐标轴单位、图例、游标读数
- 时间轴格式 HH:mm:ss，禁止原始时间戳直出
- 空数据时显示"暂无数据"占位，禁止画空白坐标系

## 禁止项（违反即打回）
- 禁止内联样式、禁止硬编码颜色值
- 禁止使用 design.md 之外的组件
- 禁止任意像素值（间距只能用 token）
- 禁止在 UI 层写业务逻辑（数据获取、报警判定必须在 service 层）
- 禁止阻塞式调用，所有数据获取异步
```

## 三、布局线框描述法（关键技巧）

不要让 AI 凭空想象布局，**先用 ASCII 线框把骨架画出来**：

```markdown
# 主界面布局（1280×800）

┌─────────────────────────────────────────────────────────┐
│ 顶部栏 h=56px 固定                                       │
│ [Logo] [系统标题]        [连接状态●] [全局报警Badge] [设置] │
├──────────┬──────────────────────────────────────────────┤
│ 左侧栏   │  主内容区（可滚动）                            │
│ w=200px  │  ┌────────────────────────────────────────┐  │
│ 固定     │  │ 概览卡片行 h=96px（4×StatCard 横排）      │  │
│          │  └────────────────────────────────────────┘  │
│ 导航：   │  ┌────────────────────────────────────────┐  │
│ ▸实时监  │  │ 报警横幅（有报警时显示，否则隐藏）        │  │
│  测      │  └────────────────────────────────────────┘  │
│ ▸历史查  │  ┌─────────────────────┬──────────────────┐  │
│  询      │  │ 节点表格            │ 实时趋势曲线      │  │
│ ▸报警记  │  │ （可伸缩）          │ （可伸缩）        │  │
│  录      │  │                     │                  │  │
│ ▸系统设  │  └─────────────────────┴──────────────────┘  │
│  置      │  ↑ 上:下 = 1:1，均可独立滚动                  │
└──────────┴──────────────────────────────────────────────┘
```

**为什么有效**：AI 对"空间关系"的文字描述理解很差，但对结构化的线框图理解很好。

## 四、五段式 Prompt 模板（直接抄）

```markdown
# 任务
生成一个 [实时监测页面] 组件。

# 技术栈约束（不可更改）
- 框架：[React 18 + TypeScript] / [Vue3 setup 语法糖] / [WPF XAML]
- 样式：[Tailwind CSS] / [CSS 变量]，禁止内联样式
- 组件库：[shadcn/ui] / [Ant Design] / [HandyControl]，只能用库内组件
- 图表：[ECharts]，配置写成独立 option 对象
- 数据：[先用 mock 常量]，文件顶部注明 "TODO: 替换为 WebSocket 数据"

# 设计规范
[粘贴 design.md 全文]

# 生成规则
[粘贴 rules.md 全文]

# 布局线框
[粘贴 ASCII 线框图]

# 交互说明
- 点击表格行 → 右侧曲线高亮该节点，其余曲线降透明度
- 点击"开始监测" → 按钮转 loading，禁用，文案改"监测中"
- 报警触发 → 顶部横幅滑入 + 该行闪烁 3 次后停止
- 空状态 / 加载中 / 错误 三态均需实现

# 输出要求
1. 先输出组件树结构（缩进列表），确认后再输出代码
2. 按容器组件 / 展示组件拆分，不要整页塞一个文件
3. 每个组件单独一个文件，给出文件存放路径
4. Props 必须有完整类型定义
5. 禁止引入规范外的第三方库
```

## 五、迭代修正的正确姿势

### ❌ 错误说法
- "中间那个不好看"
- "布局有点乱"
- "再优化一下"

### ✅ 正确说法（给参照系）
- "从顶部导航往下数第 3 个卡片区域，标题与数值之间间距从 8px 改为 16px"
- "表格区与曲线区的宽度比从 1:1 改为 3:2"
- "报警横幅出现时把下方内容顶下去（push），不要覆盖（overlay）"

### 截图反馈闭环（最强杠杆）
1. AI 生成代码
2. 浏览器打开，截图
3. 把截图 + 一句具体问题一起给 AI
4. AI 看着图改，命中率远高于纯文字描述

> 这是 Web 技术栈相对桌面 GUI 的最大优势——**AI 能"看见"自己写的界面**。

## 六、工程纪律（AI 全量开发必守）

| 纪律 | 说明 |
|---|---|
| 先骨架后细节 | 第一轮只生成布局骨架 + 占位块，确认结构对了再填内容 |
| 一功能一提交 | 每个功能单独 commit，AI 加新功能时容易破坏已有功能，可随时回滚 |
| 分层不可越 | UI 层禁止碰串口、禁止做报警判定；数据经 service 层注入 |
| 规范文件常驻 | design.md + rules.md 每次都贴，AI 无跨会话记忆 |
| 让 AI 自检 | 生成后要求 AI 输出"预期渲染结果描述"，与截图比对 |
| 类型即文档 | 数据结构先用 TS interface / C# class 定义死，再让 AI 写 UI |
