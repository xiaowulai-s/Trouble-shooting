## 一、硬约束（不可违背）

1. **扫描期只读**：串口扫描 / 识别阶段绝不向任何串口写数据，全程只 `open + read`；
   下行（手动发送）仅在「已锁定」状态开放，未锁定一律拒绝（`POST /api/send` → `409`）。
2. **串口独占**：同一串口同一时刻只能被一个程序占用；测试前必须关闭其它串口工具。
3. **串口参数固定**：`115200 / 8 / N / 1`，无流控。
4. **服务只绑 `127.0.0.1`**：不对局域网暴露。
5. **退出即清会话库**：`%TEMP%\QYH-GD300` 退出不得残留 `session.db`（长期留存靠导出）。
6. **应用名称**：上限 32 字符，拒绝空 / 纯空白，支持恢复默认。
7. **串口扫描**：独立线程 + 互斥自动检测与锁定；串口被占用时不得干扰其它程序。

### 配置优先级（明确）

- 帧格式：命令行 `--proto`（临时，不写盘） > `settings.json` 的 `layout` 键 > 内置默认 25B。
- 配置文件位置：便携优先（exe / 项目根目录 `settings.json`），不可写回退 `%LOCALAPPDATA%\QYH-GD300\settings.json`。
- 配置写入一律**合并写**（只改传入的键），避免「改名称把帧格式配置抹掉」。

## 二、工程约定

- **新功能优先作为新文件实现**，尽量不改动既有文件；改动尽量最小。
- **协议层 / 分析层为纯计算、无 IO**：协议解析器独立成模块（如 `protocol_text.py`），便于单测与复用。
- **分层不可越**：通信层 → 协议层 → 分析层 → 配置层 → 表现层；上层通过回调 / 广播消费下层数据。
- **WebSocket 广播线程安全**：跨线程投递用 `call_soon_threadsafe`；慢客户端丢弃旧消息。
- **Mock 模式**：必须提供无硬件自测的模拟数据源与自检；验证报告需覆盖 mock 与真机两种模式。
- **帧格式切换即时生效**：清解析统计、`rev` 自增、重建表格、记事件，不要求重启。
  命令行 `--proto` 指定时应提示「接口变更本次不写盘 / 需重启以完全生效」。
- **文本链路解析**：按 `\n` 切行、去 `\r`；裸数值自动映射到 `F` 字段（列名 `F(Hz)`）；`KEY=VALUE`、多字段、未知键自动成列。
- **自定义帧格式基于预设**，不允许编辑字段表本身。
- **名称变更**须同时同步 UI 表头与原生窗口标题栏（原生标题栏由壳代劳）。
- **会话与报警**：进入 / 解除都要入库（`kind` 区分 `high` 与 `high_clear`）；报警文案带字段名与单位。
- 文档管理：完成项归档、验证报告**另存新文件**（不覆盖旧报告）；Git 采用**批量提交**。

## 三、架构决策

| 决策 | 说明 |
| --- | --- |
| 三层架构 + 统一字段元数据层 | 在「通信 → 协议 → 配置桥」之上加字段元数据层，数据分流到表格 / 曲线 / 报警 / 临时存储四路输出 |
| 字段表可视化编辑 | 字段可按「键名」或「字节偏移」取值；线性换算 `y = k·x + b`；单位 / 小数位 |
| 每字段独立滤波 | `none` / `moving_avg` / `median` / `low_pass`；滤波后工程量用于制表 / 画曲线 / 判报警，原始值另存备查 |
| 文本与二进制统一配置 | 两条链路共用同一套方案 / 字段表配置 |
| 会话缓冲用 SQLite(WAL) 攒批 | 内存攒批 + 后台定时 flush；退出 `close_and_clear()`，强杀另有 `_purge` 兜底 |
| 曲线用 Canvas 手绘 | DPR 缩放；多通道单 Y 轴；`minmax` 按像素列抽稀；悬停十字线 / 点击定位 / 暂停回看 |
| 前端单文件 | 无构建链、无外部依赖，便于随 exe 打包 |

### 目录与分层对照

- 通信层 `serial_io.py`｜协议层 `protocol.py` `protocol_text.py`｜分析层 `analysis.py`
- 配置层 `schema.py` `layout_config.py` `settings.py`｜存储层 `store.py`｜推送层 `ws_push.py`
- 表现层 `web/static/index.html`｜入口 `main.py`（服务）、`desktop_main.py`（桌面壳）

## 四、环境教训（踩过的坑）

1. **pyserial 打开串口会按默认电平置位 DTR/RTS**（驱动层行为，无法完全屏蔽）；
   对 DTR 敏感的设备可能被复位 —— 已知风险，除只读外不主动操作控制线。
2. **windowed（`console=False`）构建下 `sys.stdout/stderr` 为 `None`**：
   直接写会静默退出（code 1）。必须容错，并把 traceback 落到日志或弹窗。
3. **变长 ASCII 文本流**无法用「最高频 2 字节组合」做帧头 / 帧长检测，必须走协议专用解析逻辑。
4. **PyInstaller onefile 会起子进程**：按启动器 PID 枚举窗口只会找到 `PyInstallerOnefileHiddenWindow`，
   拿不到真正的应用窗口。
5. **截图可能截到下层窗口**：需用 `PrintWindow(flag=2)` 才能拿到应用窗口真实内容。
6. **exe 自检的链路断言**：`build_exe.ps1` 自检必须显式带 `--proto 25`（或 `--proto text`），
   否则产物旁 `settings.json` 若存了别的帧格式，会「假失败」。
7. **GUI 子系统程序**：PowerShell 不会自动等待，启动 exe 需 `Start-Process -Wait`。
8. **串口扫描判据**：需「连续 3 窗口有数据 + 速率稳定 + 重复帧头」；无数据口自动跳过，约 10 s 内锁定活跃口。

### 已知未完成项

- **真机「数据级」复验**：当前 COM3（CP210x USB-UART）可打开但设备 **0 字节输出**，
  服务停在 `searching` 无法锁定，故「帧解析 / 表格 / 曲线 / 滤波 / 报警 / 下行」尚未在真机数据上闭环。
  设备就绪后按 `docs/QYH-GD300真机复验与打包验证报告.md` §1.5 六步复验即可。
- **手动下行真机验证**：同上，阻塞于设备无输出（未向设备写入，避免无意义/风险操作）。

### 按约定不在范围内的能力

- 分段 / 查表 / 多项式换算；滤波链串联；每字段独立子图与双 Y 轴
- 周期重复下行；长期归档；人工确认消警与报警备注
- 枚举文本映射（如 `MSG_TYPE` / `FLAG` 的中文名）仍显示数字
- 前端曲线缓冲上限 `max_points`（默认 20000），超限丢最旧

## 六、运行要点速查

```powershell
python service/main.py                      # 真实串口（只读识别）
python service/main.py --mock               # 无硬件自测
python service/desktop_main.py              # 桌面窗口（WebView2）
python service/desktop_main.py --self-check # exe 自检模式（不开窗）

# 打包（含 --proto 25 / --proto text 双链路自检）
powershell -ExecutionPolicy Bypass -File build/build_exe.ps1
```

- 默认端口 `8766`；访问 `http://127.0.0.1:8766`
- 验证脚本：`tools/verify_schemes.py`（8791）、`tools/verify_batch2.py`（8792），均需先起对应 mock 服务
